# 內容維護指南

這份文件說明如何在不改動程式碼的情況下，新增或修改網站上的內容：新成員、新的一屆、新學期課表、新活動紀錄。所有內容都放在 `src/content/` 底下，依 `src/content.config.ts` 定義的 schema 撰寫成 Markdown 檔案的 frontmatter。

改完內容後，務必執行以下指令確認沒有格式錯誤：

```bash
pnpm astro check   # 型別與 schema 檢查
pnpm astro build   # 確認能正常建置
```

## 新增成員／新的一屆

**路徑：** `src/content/members/<屆別>/<檔名>.md`

- `<屆別>` 是純數字目錄，例如 `14` 代表第 14 屆。**開新的一屆時，直接新增一個對應數字的目錄即可**，不用改任何程式碼。頁面會自動抓到新目錄，並顯示為「第○屆」（中文數字由 `src/lib/members.ts` 自動轉換）。
- `<檔名>` 建議用該成員的 Instagram 帳號（例如 `rainyu_05_10.md`）；沒有 IG 但有照片的話，可以用照片檔名（例如 `changfeng.md`）；兩者都沒有才用 `member-N.md` 這種通用命名。檔名本身不影響顯示內容，純粹是方便辨識用的。

**frontmatter 欄位：**

| 欄位    | 型別     | 必填 | 說明                                                   |
| ------- | -------- | ---- | ------------------------------------------------------ |
| `name`  | 字串     | 是   | 姓名                                                   |
| `title` | 字串     | 是   | 職稱，例如「社長 x 教學組長」                          |
| `order` | 數字     | 是   | 該屆內的顯示順序，數字越小排越前面（幹部通常排在最前） |
| `image` | 圖片路徑 | 否   | 相對路徑，指向 `src/assets/members/` 底下的照片檔      |
| `ig`    | 字串     | 否   | Instagram 帳號（不含 `@`）                             |
| `tags`  | 字串陣列 | 否   | 興趣標籤，預設為空陣列                                 |

**範例：**

```markdown
---
name: '余萬崧'
title: '社長 x 教學組長'
order: 0
image: '../../../assets/members/rain.jpg'
ig: 'rainyu_05_10'
tags: ['音樂', '遊戲']
---

資工系學生，喜歡嘗試跟程式有關的新事物，最近在積極學習網站跟人工智慧
```

正文是 `---` 之後的部分，內容是這位成員的自我介紹，顯示在成員卡片上。

**照片：** 先把照片放進 `src/assets/members/`，再用 `image` 欄位以相對路徑指過去。Astro 會自動處理最佳化與格式轉換，不需要自己壓縮或轉檔。

## 新增課程／新學期課表

**路徑：** `src/content/lectures/<學期>/<日期-slug>.md`

- `<學期>` 目錄命名格式為 `<民國年>-<學期>`，例如 `115-1` 代表 115 學年度上學期、`115-2` 是下學期。**開新學期時，新增對應目錄即可**，頁面會自動列出新學期，不用改程式碼。
- `<檔名>` 格式是 `<日期>-<英文 slug>.md`，例如 `2026-09-08-opening-ceremony.md`。日期方便排序；slug 讓重複性的活動，可以跨學期沿用同一個好記的名字（例如每學期都有的「期初大會」）。

**frontmatter 欄位：**

| 欄位         | 型別                           | 必填 | 說明                      |
| ------------ | ------------------------------ | ---- | ------------------------- |
| `date`       | 日期字串（`YYYY-MM-DD`）       | 是   | 上課日期                  |
| `name`       | 字串                           | 是   | 課程名稱                  |
| `slug`       | 字串                           | 是   | 給連結用的英文代稱        |
| `difficulty` | 數字（0 ~ 5）                  | 是   | 難易度                    |
| `lecturer`   | 字串                           | 是   | 講師                      |
| `location`   | 字串                           | 是   | 上課地點                  |
| `tags`       | 字串陣列                       | 否   | 分類標籤，預設為空陣列    |
| `type`       | `'主線'` 或 `'支線'`           | 是   | 課程屬性                  |
| `timeline`   | 陣列（每項含 `time`、`event`） | 否   | 課程流程表，`time` 可省略 |
| `slide`      | URL                            | 否   | 投影片連結                |
| `slido`      | URL                            | 否   | Slido 互動連結            |
| `cowrite`    | URL                            | 否   | 共筆連結                  |
| `kktix`      | URL                            | 否   | 報名連結                  |

**範例：**

```markdown
---
date: '2026-09-08'
name: '期初大會'
slug: 'opening-ceremony'
difficulty: 0
lecturer: '萬崧'
location: '挺生大樓 307 教室'
tags: ['期初大會']
type: '主線'
timeline:
  [
    { 'time': '18:00 ~ 18:30', 'event': '場佈、活動準備' },
    { 'time': '18:30~19:00', 'event': '社團介紹' },
  ]
---

📢 認識社團、認識彼此。本學期課程地圖搶先看，還有社費用途全公開——開源社團，連帳目都 open source。
```

正文是課程簡介，顯示在課程卡片／詳情頁上。

## 新增活動紀錄

**路徑：** `src/content/events/<類型>-<日期>-<slug>/index.md`，並在同一個目錄放一張 `photo.jpg`。

- 每筆活動紀錄是**獨立目錄**（而非單一檔案），因為每筆紀錄都有自己專屬的一張照片，跟講師／成員照片可能重複使用不同，不需要另外維護一個共用的圖片目錄。
- 目錄命名建議格式：`<類型>-<日期>-<slug>`，例如 `community-2026-08-21-hitcon`。這個命名只是方便瀏覽，實際分類依 frontmatter 的 `type` 欄位為準。

**frontmatter 欄位：**

| 欄位    | 型別                                                                       | 必填 | 說明                           |
| ------- | -------------------------------------------------------------------------- | ---- | ------------------------------ |
| `date`  | 日期字串（`YYYY-MM-DD`）                                                   | 是   | 活動日期                       |
| `name`  | 字串                                                                       | 是   | 活動名稱                       |
| `desc`  | 字串                                                                       | 否   | 簡短描述                       |
| `type`  | `'camp'`、`'community'`、`'competition'`、`'lecture'`、`'others'` 其中之一 | 是   | 活動分類                       |
| `image` | 圖片路徑                                                                   | 否   | 通常是同目錄下的 `./photo.jpg` |

**範例：**

```markdown
---
date: '2026-08-21'
name: 'HITCON'
desc: '駭客年會'
type: community
image: ./photo.jpg
---
```

**新增步驟：**

1. 在 `src/content/events/` 底下新增目錄，依上述命名慣例取名。
2. 把活動照片存成目錄裡的 `photo.jpg`。
3. 新增 `index.md`，填入上面的 frontmatter 欄位。
4. 執行 `pnpm astro check` 跟 `pnpm astro build` 確認沒問題。

## 常見問題

**改完內容後畫面沒更新？**
確認開發伺服器有在跑（`pnpm dev`），或用 `astro dev --background` 搭配 `astro dev logs` 檢視背景執行的輸出。

**`pnpm astro check` 報錯說欄位型別不對？**
通常是 frontmatter 漏填必填欄位，或欄位型別跟 `src/content.config.ts` 定義的 schema 不符（例如把數字寫成字串）。錯誤訊息會標出是哪個檔案、哪個欄位有問題。

**中英文版本的內容要分開寫嗎？**
不用。`lectures`、`members`、`events` 這三個 collection 的內容本身**只有繁體中文一種版本**，不隨語言切換。頁面上的 UI 文字（標題、按鈕、說明文字等）才有中英文兩份，寫在各頁面元件自己的 `content` 字典裡，跟這裡的內容資料分開維護。
